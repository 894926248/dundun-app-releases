# 分发约定

每个 `distributions/<distribution-id>/` 目录对应一个独立分发包，自有品牌标识为 `dundun`，代理分发使用各自稳定的标识。

## 发布文件

- Release tag：`<distribution-id>-v<version>`，例如 `dundun-v2.0.9`。这是命名示例，不代表版本已发布。
- Release 名称包含品牌名和版本。
- 安装包命名包含分发标识、版本、操作系统和架构，避免代理包与自有包混淆。
- 更新清单与它引用的安装包属于同一分发、同一版本；文件名遵循实际更新器要求，不能仅为命名统一破坏更新器协议。
- 安装包、差分文件和校验文件存放在对应 Release 的 assets 中。

## 更新隔离

客户端构建时固定 distribution-id，更新检查必须按该标识读取对应入口，并核对返回的分发身份，不能依赖整个仓库的 latest Release，也不能回退至其他代理或自有包。

后续接入更新器时，在各分发目录维护真实的更新入口。先上传并验证完整 Release assets，再切换该分发入口；发布失败不改入口。不为尚未发布的版本填写虚假下载链接。

代理定制打包时还需独立配置应用身份、品牌、后端地址、安装位置及用户数据目录；这些属于私有源码中的打包配置。本仓库目录划分本身不实现代理定制或自动更新。

## 公开边界

这里的目录、发行文件和下载地址全部公开。不得上传账号密钥、仓库 Token、代理管理凭据、生产配置、用户数据或私有源码。代理分发目录只填写允许公开的信息。
